概述

什么是 PyTorch 分布式？

PyTorch 分布式 (torch.distributed) 是 PyTorch 提供的多进程/多机训练和推理框架，支持：

  • ✅ 数据并行：每个 GPU 处理不同数据
  • ✅ 张量并行：模型切分到多个 GPU（Nano-vLLM 使用）
  • ✅ 流水线并行：模型层分布到不同 GPU
  • ✅ 多机训练：跨多台机器的分布式执行

通信后端

PyTorch 支持多种通信后端，各有适用场景。

NCCL (NVIDIA Collective Communications Library)

最适合 GPU 多卡/多机场景

特点：

  • ✅ 性能最优：专为 GPU 优化，支持 NVLink
  • ✅ 自动优化：根据拓扑结构选择最优路径
  • ✅ 支持 GPU Direct RDMA：绕过 CPU，直接 GPU-GPU 传输
  • ❌ 仅限 NVIDIA GPU

Nano-vLLM 使用：

Gloo

适用于 CPU 或少量 GPU

特点：

  • ✅ 跨平台：支持 Linux/Windows/macOS
  • ✅ CPU/GPU 混合：可在 CPU 上运行
  • ❌ 性能较低：相比 NCCL 慢 2-5x
  • ❌ 不支持 NVLink

适用场景：

  • CPU 集群训练
  • 开发/调试（单机多卡）
  • 跨操作系统部署

MPI

适用于超算/科研场景

特点：

  • ✅ 生态成熟：MPI 标准实现
  • ✅ 超算优化：支持 InfiniBand 等高速网络
  • ✅ 灵活配置：支持丰富的进程拓扑
  • ❌ 配置复杂：需要安装 MPI 实现

适用场景：

  • 国家超算中心
  • 科研计算集群
  • 自定义网络拓扑

集体通信原语

PyTorch 提供多种集体通信（Collective Communication）原语。

1. Barrier - 同步点

作用：同步所有进程

示例：

2. Broadcast - 广播

作用：将 src 进程的数据广播到所有进程

示例：模型参数初始化

3. All-Reduce - 全局归约

作用：对所有进程的数据执行归约操作，结果返回给所有进程

归约操作：

  • ReduceOp.SUM：求和（最常用）
  • ReduceOp.PRODUCT：乘积
  • ReduceOp.MAX：最大值
  • ReduceOp.MIN：最小值
  • ReduceOp.AVG：平均值

示例：张量并行梯度同步

4. Reduce - 归约

作用：对所有进程的数据执行归约，结果只发送到 dst 进程

示例：汇总损失

5. All-Gather - 全收集

作用：收集所有进程的数据到每个进程

示例：收集各 GPU 的预测结果

6. Scatter - 分发

作用：将数据分发到不同进程

性能对比

操作数据量时间复杂度
Barrier0 字节O(log P)
BroadcastN 字节O(N)
All-ReduceN 字节O(N)
ReduceN 字节O(N)
All-GatherN×P 字节O(N×P)
ScatterN×P 字节O(N×P)

注：P = 进程数

说明：

  • 实际性能取决于硬件配置（NVLink/PCIe/网络）
  • NCCL 在 NVLink 上可达到最高性能
  • 延迟和带宽因 GPU 型号（A100/H100）和配置而异

常见问题

Q1: 什么时候需要使用 Barrier？

需要：

  • ✅ 创建/删除共享资源（共享内存、文件）
  • ✅ 同步性能测量
  • ✅ 确保数据准备就绪

不需要：

  • ❌ All-Reduce/All-Gather 等集体通信（已内置同步）
  • ❌ 独立的数据处理

Q2: NCCL vs Gloo 如何选择？

总结

关键要点

  1. Barrier 是同步原语，确保所有进程到达同一点
  2. NCCL 是 GPU 首选，性能最优
  3. 集体通信自动同步，无需额外 barrier
  4. 环境变量配置，避免硬编码
  5. 始终清理资源，防止泄漏

在 Nano-vLLM 中的作用

核心价值：

  • ✅ 张量并行支持大模型
  • ✅ 自动通信优化
